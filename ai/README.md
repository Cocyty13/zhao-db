# AI-Optimized Structure for Zhao Roleplay Database

โครงสร้างนี้ถูกออกแบบมาเพื่อให้ AI (Grok / GPT) สามารถอ่าน เขียน และจดจำข้อมูลสำหรับการเล่นบทบาทสมมติที่ซับซ้อนและยาวนานได้อย่างมีประสิทธิภาพ

## หลักการออกแบบ

### 3 ชั้นข้อมูล (Layered Knowledge)

| ชั้น | ชื่อไฟล์/โฟลเดอร์ | ความถี่ที่ AI ใช้ | คำอธิบาย |
|------|-------------------|------------------|----------|
| **L1** | `CORE_SNAPSHOT.md` | ทุกฉาก | สถานะปัจจุบันของเรื่อง + ตัวละครหลัก + Plot ที่กำลังดำเนิน |
| **L2** | `ACTIVE_PLOT.md`<br>`QUICK_FACTS.md`<br>`CHARACTER_CARDS/` | บ่อย | ข้อมูลที่ต้องใช้บ่อยระหว่างเล่น |
| **L3** | SQLite เดิม + Archive | นาน ๆ ครั้ง | ข้อมูลลึก ประวัติศาสตร์ Events เก่า |

### หลักการสำคัญ
- **SQLite ยังคงเป็น Source of Truth**
- ไฟล์ในโฟลเดอร์ `ai/` เป็น "View" ที่อ่านง่ายสำหรับ AI
- ทุกการเปลี่ยนแปลงสำคัญต้องสะท้อนกลับไปที่ SQLite
- ไฟล์ Markdown ต้องสั้น กระชับ และมีโครงสร้างชัดเจน

## โครงสร้างโฟลเดอร์

```text
ai/
├── README.md                 # ไฟล์นี้
├── CORE_SNAPSHOT.md          # สำคัญที่สุด - อ่านทุกครั้งก่อนเริ่มฉาก
├── ACTIVE_PLOT.md            # Plot threads ที่กำลังดำเนินอยู่
├── QUICK_FACTS.md            # Facts สำคัญที่ต้องจำ
├── RELATIONSHIP_MATRIX.md    # ความสัมพันธ์แบบตาราง
├── CHARACTER_CARDS/          # การ์ดตัวละครหลักแยกไฟล์
│   ├── 01_องค์ชายรอง.md
│   ├── 02_หลี่หรง.md
│   ├── 03_ซัวเหยา.md
│   ├── 04_หลี่เชี่ย.md
│   └── 05_เสิ้นอวี้หลัน.md
└── ARCHIVE/                  # สรุปช่วงเก่า (ถ้ามี)
```

## Workflow การใช้งานกับ AI

1. **ก่อนเริ่มฉาก** → อ่าน `CORE_SNAPSHOT.md` + `ACTIVE_PLOT.md`
2. **ระหว่างเล่น** → อัปเดตเฉพาะส่วนที่เปลี่ยน
3. **จบฉากสำคัญ** → บันทึกลง SQLite + ปรับปรุง Snapshot
4. **ทุก 5-10 ฉาก** → ทำ Continuity Check
