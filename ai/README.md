# AI-Optimized Structure for Zhao Roleplay Database

โครงสร้างนี้ถูกออกแบบมาเพื่อให้ AI (Grok / GPT) สามารถอ่าน เขียน และจดจำข้อมูลสำหรับการเล่นบทบาทสมมติที่ซับซ้อนและยาวนานได้อย่างมีประสิทธิภาพ

**สถานะ:** พร้อมใช้งาน (Usable)

---

## หลักการออกแบบ

### 3 ชั้นข้อมูล (Layered Knowledge)

| ชั้น | ชื่อไฟล์/โฟลเดอร์ | ความถี่ที่ AI ใช้ | คำอธิบาย |
|------|-------------------|------------------|----------|
| **L1** | `CORE_SNAPSHOT.md` | ทุกฉาก | สถานะปัจจุบันของเรื่อง + ตัวละครหลัก + Plot ที่กำลังดำเนิน |
| **L2** | `ACTIVE_PLOT.md`<br>`QUICK_FACTS.md`<br>`CHARACTER_CARDS/`<br>`RELATIONSHIP_MATRIX.md` | บ่อย | ข้อมูลที่ต้องใช้บ่อยระหว่างเล่น |
| **L3** | SQLite เดิม + `PLOT_UPDATES.md` | นาน ๆ ครั้ง | ข้อมูลลึก ประวัติศาสตร์ Events เก่า |

### หลักการสำคัญ
- **SQLite ยังคงเป็น Source of Truth**
- ไฟล์ในโฟลเดอร์ `ai/` เป็น "View" ที่อ่านง่ายสำหรับ AI
- ทุกการเปลี่ยนแปลงสำคัญควรสะท้อนกลับไปที่ SQLite ในภายหลัง
- ไฟล์ Markdown ถูกออกแบบให้สั้น กระชับ และมีโครงสร้างชัดเจน

---

## โครงสร้างโฟลเดอร์ (ปัจจุบัน)

```text
ai/
├── README.md                     # ไฟล์นี้
├── CORE_SNAPSHOT.md              # สำคัญที่สุด - อ่านทุกครั้งก่อนเริ่มฉาก
├── ACTIVE_PLOT.md                # Plot threads ที่กำลังดำเนินอยู่
├── QUICK_FACTS.md                # Facts สำคัญที่ต้องจำ
├── RELATIONSHIP_MATRIX.md        # ความสัมพันธ์แบบตาราง
└── CHARACTER_CARDS/
    ├── 01_องค์ชายรอง.md
    ├── 02_หลี่หรง.md
    ├── 03_ซัวเหยา.md
    ├── 04_หลี่เชี่ย.md
    ├── 05_เสิ้นอวี้หลัน.md
    ├── 06_ฮ่องเต้.md
    ├── 07_แม่ทัพอู่.md
    └── 08_แม่ทัพหยาง.md
```

---

## Workflow การใช้งานกับ AI

1. **ก่อนเริ่มฉาก** → อ่าน `CORE_SNAPSHOT.md` + `ACTIVE_PLOT.md`
2. **ระหว่างเล่น** → อ้างอิง CHARACTER_CARDS และ QUICK_FACTS ตามต้องการ
3. **จบฉากสำคัญ** → อัปเดต CORE_SNAPSHOT และ ACTIVE_PLOT
4. **ทุก 5-10 ฉาก** → ทำ Continuity Check และบันทึกลง SQLite
